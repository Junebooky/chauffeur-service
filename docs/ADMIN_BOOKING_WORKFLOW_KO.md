# Chauffeur 관리자 예약 처리 — 2026-11-23

## 핵심 원칙

- **예약 승인에 실제 차량이나 기사 배정은 필수가 아니다.** 고객이 예약한 차종은 클래스 기준으로 접수되고, 실제 차량·기사 배정은 나중에 운영자가 처리한다.
- **공개 \`/admin\`:** 실제 Supabase 예약 진행 현황을 한국어로 조회. 고객 개인정보와 상세 경로·결제 금액은 표시하지 않는다. 각 예약의 **예약 처리하기** 버튼으로 보호된 운영 모드를 연다.
- **관리 \`/admin/live\`:** 관리자 이메일 링크(또는 기존 비밀번호)로 로그인 후 고객 정보 확인, 예약 접수·확정·서비스 시작·완료, 임의 입금 확인 기록, 선택적 공급업체/기사 배정, 업체·기사 등록 가능.
- 로그인/권한 확인은 서버에서 \`requireStaff\`로 수행한다. 공개 대시보드에 실제 데이터 수정 권한을 추가하지 않는다.

## 예약 흐름

| 단계 | 운영자 행동 | DB 상태 |
|---|---|---|
| 요청 접수 | 고객 웹사이트에서 제출 | \`requested\` |
| 요청 확인 | 예약 정보를 검토 | \`reviewing\` |
| 입금 안내 (선택) | 계좌이체/PayPal 안내 | \`awaiting_deposit\` |
| 예약 승인 | **배차 없이도** 바로 확정 가능 | \`confirmed\` |
| 서비스 시작 | 실제 이동 시작 | \`in_progress\` |
| 서비스 완료 | 종료 처리 | \`completed\` |

필요 시 신규 요청을 바로 \`confirmed\`로 전환할 수 있다. \`declined\` 및 \`cancelled\`는 필요할 때만 사용한다. 상태 전환은 \`chauffeur.advance_reservation_v1\` RPC에서 검증·직렬화·감사 기록하며, 화면의 과거 상태로 덮어쓰려는 요청은 409로 거절한다.

## 결제

- 예약금은 선택적이다. 입금 요청 단계로 보내지 않고도 승인할 수 있다.
- 관리자 입금 기록은 **실제 은행·PayPal 확인 후에만** 작성한다. 화면에서 금액을 입력한다고 자동으로 결제되거나 고객에게 인보이스가 발송되는 기능은 없다.

## 운영 확인

- \`GET /api/admin-overview\`: 공개된 비식별 예약 요약만
- \`GET /api/admin\`: 관리자 토큰 필요
- \`POST /api/admin\` action \`advance\`: 예약 ID, expected_status, 새로운 status 필요. 서버에서 권한 및 상태 전환 검증
- UI 문구는 전부 한국어로 제공하되 기존 Chauffeur의 블랙·차콜·실버 디자인 유지
- Supabase Auth의 이메일 링크는 **Redirect URLs 허용 목록**에 실제 운영 \`https://chauffeur-service-bice.vercel.app/admin/live\`이 포함되어야 한다. 공유 프로젝트의 다른 Auth 설정은 함부로 변경하지 말 것. 관리자 인증 메일이 오지 않으면 SMTP 설정도 확인할 것.
- 빌드/테스트: \`npm run check && npm test && npm run build\`
